# TestForge 开发规格（DEV-SPEC）

> v0.1 · 2026-10-19 · 功能需求的完整来源见 `docs/PRD.md`，本文件只定范围边界与验收口径
> 状态：已确认（2026-10-19）

## 一句话产品

TestForge 是自用/内部的一站式测试平台：测试管理（项目/需求/迭代/用例/缺陷/计划）+ 接口自动化 + Web UI 自动化 + APP 自动化 + AI 辅助（用例生成、聊天助手、智能体）+ CI 集成。

**功能基线**：源自内部功能调研（2026-10-19 完成并固化为 PRD），仓库内不保留调研过程资料。
**自研边界**：品牌、Logo、文案、视觉全部自研，不逐像素对标任何现有产品；调研中发现的目标产品已知缺陷（如用例生成工作台卡死）不复刻。

## 做什么

- 测试管理 ALM 子集：项目、需求、迭代、任务、版本、缺陷、用例（树形模块）、测试计划、控制台统计
- 接口测试：接口定义（Monaco 编辑）、环境变量、用例/集合/批量/计划、执行日志与报告、CI Invoke API（Token 鉴权 GET 触发）
- Web UI 自动化：Playwright 执行器、用例/元素库、录制、执行中心、报告；后期 AI Agent 驱动浏览器
- APP 自动化：设备农场（ADB 扫描/注册/投屏/群控）、Appium 用例、Monkey、启动耗时、性能、抓包、报告
- AI 层：模型中心（OpenAI 兼容多供应商）、聊天助手（SSE）、Token 计量、智能体广场、Skill 技能、（可选）知识库
- 平台：RBAC 九件套（用户/角色/菜单/部门/岗位/字典/参数/日志/公告）、监控（在线/服务器/缓存/文件）、定时任务、工作流、通知中心、CI

## 不做什么（本轮基线）

- 插件市场（对标产品中为空壳，降级为扩展点设计，不实现）
- OAuth 第三方登录与扫码登录（内部平台用账号密码 + 验证码即可；扩展点保留）
- 逐像素 UI 还原、对标产品的品牌/文案复制
- 多租户/SaaS 化

## 范围边界

- 单组织（内部使用），部门树仅用于归属与数据权限展示
- 执行引擎默认单机内置模式（Playwright/Appium 在服务进程内调度）；P8 再做分布式节点（配对码 Agent）
- 知识库（RAGFlow）为可选外置依赖，不阻塞主链路；无 RAGFlow 时 AI 功能不引用知识库

## 验收口径

- 每阶段：`uv run pytest -q`（server）与 `pnpm test`（web）退出码 0；本阶段 API 契约测试绿
- 用户可见主链路每轮跑冒烟（登录 → 本阶段核心页 → 一条闭环操作）
- P2 起：CI Invoke API 与对标产品 12 种 opt 语义等价（runrequest/runcollection/runtestcase/runbatch/runplan/runstatus/batchstatus/plan_progress/cancelbatch/coordinator_status/ping）
- P4 门禁：1 条录制回放用例全链路绿；P5 门禁：1 台模拟器设备全链路绿

## 阶段路线（摘要，详见批准计划）

P0 基座 → P1 测试管理 → P2 接口测试 → P3 AI 层 → P4 UI 自动化 → P5 APP 自动化 → P6 任务与工作流 → P7 CI+通知 → P8 分布式化

总量估算 5-7 人月（单人 + AI 辅助）；P0-P2 完成即有可用的「测试管理 + 接口自动化」内部平台。
