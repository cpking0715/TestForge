# ADR-0001 技术栈与架构基线

日期：2026-10-19 · 状态：已接受

## 背景

TestForge 为全量复刻对标产品功能的新建项目，需确定技术栈与仓库架构。对标产品实测栈：React 19 + Vite + TailwindCSS 前端；Python 3.12 后端（FastAPI 特征）+ nginx + Redis +（外置 RAGFlow）。

## 决策

- 后端 Python 3.13 + FastAPI（同步 SQLAlchemy 2.x 起步；内部平台规模下同步足够，复杂执行引擎阶段再评估 async）
- 数据库 PostgreSQL，缓存/会话 Redis（docker-compose 本地起）；测试用 SQLite（模型保持可移植类型，不使用 PG 专有列类型）
- 认证：JWT Bearer + 算术图形验证码（Pillow 生成，内存 TTL 存储，后续换 Redis）
- 前端 React 19 + Vite + TypeScript + TailwindCSS，`features/` 功能域组织，API 调用只在 api 层，TS 类型从 OpenAPI 生成（openapi-typescript）
- 执行引擎：Playwright（Web）、Appium + scrcpy + ADB（APP）、mitmproxy（抓包）、APScheduler（定时）
- 仓库 monorepo：`apps/server`、`apps/web`、`apps/agent`（P8 执行节点）、`libs/`（跨端共享，三次法则后才建）、`docs/`、`deploy/`

## 理由

- 后端语言与对标产品一致，功能语义对标成本低；也是团队默认栈
- PostgreSQL 替代默认 SQLite：300 级 API、队列、Token 计量的规模需要并发写与 JSON 查询；测试仍可用 SQLite 保持零依赖跑测
- 前端与对标产品同家族（React + Tailwind），信息架构与交互模式可平移理解

## 后果

- 模型层禁用 PG 专有类型（JSONB 等）直到引入迁移分叉策略；需要 JSON 时用 `sa.JSON`
- `apps/agent` 在 P8 前不建目录，避免空壳
